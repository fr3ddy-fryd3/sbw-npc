| Файл или каталог | Назначение |

| [InfantryMovementGameTests.kt](../src/gameTest/kotlin/com/sbwnpc/squad/gametest/InfantryMovementGameTests.kt) | Сцены движения, создание NPC и отряда, выдача MOVE, проверки прибытия, запись состояния навигации |
| [movement_arena.nbt](../src/gameTest/resources/data/sbwnpc/structure/movement_arena.nbt) | Пустой шаблон размером 24 × 8 × 12; пол и препятствия ставят методы тестов |

| `build/gametest/server/` | Изолированный мир, настройки и логи тестового сервера |
| `build/reports/gameTest/<имя>/` | CSV каждого сценария, краткий результат TXT и `server.log` |

## Запуск

```bash
./gradlew runGameTestServer -PgameTestReportName=movement-baseline
```

После первого скачивания зависимостей можно добавить `--offline`. Имя отчёта допускает буквы ASCII, цифры, дефис и подчёркивание. Повтор с тем же именем перезаписывает отчёт; для сравнения версий задавайте разные имена. Без параметра используется `latest`.

Сервер сам завершает работу. Успешный прогон возвращает код 0, провал обязательного сценария — ненулевой код. Это отдельный запуск: `./gradlew test` по-прежнему выполняет JUnit и не запускает GameTest.

## Текущие сценарии

| Метод | Сцена | Проверка |
|---|---|---|
| `moveAcrossFlatGround` | Каменный пол, NPC в `(3.5, 1, 6.5)`, цель `(20, 1, 6)` | NPC тикает и подходит к цели MOVE на 1.5 блока |
| `moveOntoOneBlockPlatform` | Тот же маршрут; начиная с `x=12` пол поднят на один блок, цель `(20, 2, 6)` | NPC подходит к цели и действительно стоит на высоте платформы |

Координаты относительны шаблону. NPC создаётся через зарегистрированный `ModEntities.NPC`, получает класс стрелка, обычное снаряжение SBW и регистрируется через `SquadManager`. Приказ и цель задаются штатными методами менеджера. После начального размещения тест не меняет координаты, путь, скорость или состояние мозга NPC. Прибытие проверяется по положению живой сущности. Лимит сценария — 400 тиков, с явным отказом на тике 399.

CSV записывается каждый тик: координаты относительно сцены, расстояние до цели, скорость и вектор движения, контакт с землёй, горизонтальное столкновение, поза, состояние пути и индекс следующего узла, конечная достижимость и координаты цели `MoveControl`. Цель контроллера записана в абсолютных координатах мира. TXT содержит UUID, флаг `noAi`, реальные классы навигатора и контроллера, результат и тик завершения. Официальное завершение теста и ошибки загрузки смотрите в `server.log`.

GameTestServer выполняет тики ускоренно. Время запуска процесса не равно длительности маршрута в игре; игровые секунды считаются как число тиков / 20. UUID, экипировка и случайные задержки AI пока не фиксируются, поэтому тик прибытия может отличаться между прогонами.

## Проверка чувствительности стенда

```bash
./gradlew runGameTestServer -PgameTestReportName=negative-control -PgameTestNegativeControl=true
```

Эта команда намеренно отключает AI только у NPC ровного маршрута. Ожидаемый результат: `moveAcrossFlatGround` падает по таймауту, NPC остаётся в начале маршрута, платформенный сценарий проходит, Gradle возвращает ошибку. Параметр обрабатывается только кодом `src/gameTest`; в игровой JAR этот код не попадает.

## Границы проверки

Проверены одиночный MOVE и подъём на обычный полный блок. Здесь работают настоящие SmartBrainLib, `VehicleAwareNavigation`, `NpcMoveControl`, коллизии и серверные тики. Боевой отряд, построение линии, стрельба, укрытия, падения в ямы и блоки Dynamic Trees пока не покрыты этими сценами. Успех двух маршрутов не подтверждает исправление тактики или пользовательского случая остановки отряда.

При запуске SBW сообщает о недоступном клиентском `ClientLevelMixin` на dedicated server; проверенные запуски после этого загружают моды и завершают GameTest. Это сообщение зависимости сохраняется в отчёте и не скрывается стендом.

Основа конфигурации: [NeoForge GameTest для 1.21.1](https://docs.neoforged.net/docs/1.21.1/misc/gametest/) и [ModDevGradle: отдельные source sets и выбор loadedMods](https://github.com/neoforged/ModDevGradle).
